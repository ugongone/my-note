Claude Opus 4.8 一般提供

価格据え置きで「誠実さ」とエージェント性能を底上げ。Dynamic Workflows で並列実行の主力へ。

1. 何が発表されたか

2026年5月28日、Anthropic がフラッグシップ「Claude Opus 4.8」をGA。価格は4.7据え置きのまま、エージェント性能を底上げした約41日ぶりの更新。

  • •Anthropic のフラッグシップ最新版で、エージェント的コーディング・computer use・多分野推論を強化
  • •価格は 4.7 据え置きのまま性能を底上げ。Opus 4.7 から約41日ぶりの更新
  • •主要クラウドと Claude Code / Cowork / Agent SDK で同日提供開始
提供開始日2026年5月28日（GA）

3. 目玉機能：Dynamic Workflows 新機能

大きな作業を Claude が自分で小タスクに分解し、数百のサブエージェントを並列実行してから検証して報告する 4.8 の目玉機能。Claude Code 向けの研究プレビュー。

ざっくり言うと

  • •Claude が オーケストレーション用の台本（JavaScript）を自分で書き、それをランタイムが裏で実行する仕組み
  • •単一セッションで 数十〜数百体（累計最大1,000体・同時は約16体）のサブエージェントを並列実行
  • •各エージェントが調査・修正・検証・互いの主張への反証（敵対的検証）を分担し、生き残った結論だけ返す
  • •用途例：コードベース全体のバグ探索、数十万行のコード移行、セキュリティ監査、横断リサーチ

従来のサブエージェント呼び出しとの違い

観点 従来のサブエージェント Dynamic Workflows
指揮役Claude がターンごとに次の手を判断Claude が台本(script)を書き、ランタイムが実行
中間結果すべて Claude のコンテキストに溜まる台本の変数に保持。最終結果だけ返る
規模実質4〜5体程度数十〜数百体（累計最大1,000体）
品質の作り込み単純な並列実行敵対的検証など品質パターンを台本に組める
実行会話ターン内バックグラウンド実行（セッションは応答可能）
補足: 両者は排他ではなく、Dynamic Workflows は内部でサブエージェントを呼ぶ。決まった手順・予測可能なコストならサブエージェント、大規模・探索的なら Dynamic Workflows が向く。

どう使う？

デフォルトでは発動しない。次のどちらかで明示的に起動する。

  • •プロンプトに「workflow」と書く（その単語が認識されファンアウトを計画）
  • •ultracode をオン（/effort メニュー）→ effort を xhigh にし、使うか否かを Claude が自動判断
  • •auto モードの併用が推奨。まず小さく区切ったタスクで試すのが安全

コストと対象プランの注意

便利な反面、消費は大きい。使う前に押さえるべき点。

  • •公式が「通常セッションより大幅にトークンを消費しうる」と明記。まず小さく区切って試すこと
  • •プレミアム料金はなく、標準の Opus 4.8 レート（$5／$25）でサブエージェント数ぶん積み上がる。数百体に展開すれば消費もその分膨らむ
  • •対象は Enterprise / Team / Max プラン。Pro は対象外
  • •研究プレビュー段階。組織側で無効化（disableWorkflows）も可能
具体的な消費量について: Opus 4.8 で Dynamic Workflows を実際に回したトークン量・コストの公式実測値は、機能が提供開始直後のため現時点で確実な一次情報が未確立。実際の消費は必ず実トラフィックで計測すること。

4. Effort（労力）制御の改良 改良

「どれだけ じっくり考えさせるか」を選ぶ設定。Opus 4.5 から続く既存機能で、4.8 では新登場ではなく「使える場所」と「配分」が変わった点が要点。

  • •Opus 4.5（2025/11）から続く機能で、4.8 で新登場したものではない
  • •4.8 で claude.ai・Cowork のGUIにも開放、全プランで利用可能に
  • •各レベルのトークン配分を再調整：medium 増・high 減・xhigh 大幅増
  • •既定は high。難タスクは extra（Claude Code では xhigh）／ max を選択可能
トークン消費の心配について: 同じ high なら 4.8 は 4.7 より思考トークンがむしろやや減る方向（high が下方再調整）。コーディングでは「4.7 既定と同程度のトークンで性能向上」と公式が説明。トークンが大きく増えるのは xhigh を明示指定したときなので、何もしなければ過度な増加は起きにくい。

5. 「誠実さ」の向上という方向性

「できないことはできないと言う」モデルへ。テストを誤魔化す振る舞いが 4.7 比で約4分の1に減り、長時間タスクをAIに任せる際の信頼性を重視した設計思想が前面に出ている。

  • •Anthropic は「これまでで最も誠実なモデル」と位置づけ
  • •テストのハードコードやショートカットで成功を装う振る舞いを 4.7 比で約4分の1に低減
  • •ツール起動の改善：必要なツール呼び出しをスキップしにくくなった（4.7 の課題に対応）
  • •compaction 後も長い agentic トレースが脱線しにくく、長文脈の品質が向上
  • •adaptive thinking でターンごとに思考要否を判断し、無駄な thinking トークンを削減
引用: 「A model that quietly cuts corners to appear successful is far less useful than one that reports problems honestly—even when the honest answer is that it couldn't complete the task.」

6. Mythos級モデルへの布石

同時に「Mythos 級モデルを数週間以内に広く提供」と予告。汎用フラッグシップを底上げしつつ、より強力なセキュリティ特化モデルの一般化へ地ならしする動き。

  • •発表と同時に「Mythos 級モデルを数週間以内に広く提供する見込み」と予告
  • •Mythos は現在 Project Glasswing パートナーに限定提供（防御目的のサイバー利用に限定）
  • •Opus 4.8 は、より強力なモデルの一般化に向けた地ならしという位置づけ
同週、OpenAI が対抗モデル GPT-5.5-Cyber を日本のメガバンクに提供する動きもあり、フロンティアのサイバー能力が安全保障の文脈で各国に展開され始めている（本週報③参照）。

  • •価格据え置きでエージェント実務の信頼性を引き上げた、実利重視の更新
  • •SWE-bench で GPT-5.5 と拮抗、computer use では公称で GPT-5.5 を上回る
  • •大規模並列実行＋誠実さ改善で、長時間タスクをAIに委ねる流れを後押し
  • •年内のさらなる更新・Mythos 級一般化が見込まれ、主力モデルの地位を固めつつある
